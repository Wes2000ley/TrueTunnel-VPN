# TrueTunnel 3.1.0-preview.1

An evaluation preview of the modern Windows desktop. This is not a stable
release and has not completed the elevated real-network qualification of the
new desktop/worker privilege boundary. Do not use this preview for a
security-critical deployment.

## Download and run

Download **TrueTunnel-3.1.0-preview.1-windows-x64.zip** from the
[GitHub release](https://github.com/Wes2000ley/TrueTunnel-VPN/releases/tag/v3.1.0-preview.1).
Extract the entire ZIP into its own directory, then open `TrueTunnel.exe`.
Keep the supplied `wintun.dll` next to it. Do not run the application from
inside the ZIP or mix its files with an older release.

- Windows 11 or Windows Server 2022 or newer, x64.
- Microsoft Edge WebView2 Evergreen Runtime is required for the GUI. Windows 11
  normally includes it; this ZIP does not install it. If missing, obtain the
  runtime from [Microsoft](https://developer.microsoft.com/microsoft-edge/webview2/).
- Node.js, npm, .NET, OpenSSL, and a separate Visual C++ Redistributable are not
  runtime prerequisites for this build.
- Opening the GUI does not require Administrator privileges. Starting a tunnel
  requests UAC approval for a separate native worker under the same Windows
  user. Elevation using another administrator's credentials is not supported.
- `TrueTunnel.exe` is not Authenticode-signed. Windows may display an unknown
  publisher or reputation warning. The included checksum manifest verifies
  file integrity, not publisher identity; do not disable Windows protections.

## What changed

- Replaced the ImGui desktop with an embedded React/TypeScript interface hosted
  in WebView2: aligned connection controls, responsive cards, light/dark/system
  themes, accessible dialogs, keyboard navigation, searchable activity, and
  reduced-motion support.
- Separated the unelevated interface from the on-demand elevated network worker.
  Access keys remain in native memory, outside JavaScript, JSON, and the DOM.
  Local control messages are bounded and checked against process identity.
- Retained the native Schannel TLS 1.3 / wolfSSL DTLS 1.3 engine, optional
  heartbeat/reconnect, deterministic Wintun identity, TCP session renewal,
  and UDP traffic-key updates.
- Removed Conan, ImGui, and FreeType from the active build. The frontend is
  embedded in the executable, with pinned dependencies and bundled notices.

The release includes the transport and recovery work since V3 as recorded in
the [changelog](../../CHANGELOG.md). Older V3 binaries do not represent the
current security design; this preview does not establish wire compatibility
with them. Use matching versions at both ends when evaluating it.

## Validation and remaining gates

The release's `VALIDATION.md` records the exact source revision, tool versions,
commands, observed test counts, and artifact checks from publication. Automated
coverage includes native secure transport tests, IPC boundaries, Wintun loader
and identity checks, daemon lifecycle, the actual unelevated EXE rendering test,
and the headless frontend/axe matrix.

**Not qualified for this preview:** elevated real-Wintun TCP/UDP E2E, actual
GUI Connect/Start server/Disconnect/tray behavior across the new privilege
boundary, a fresh real-tunnel throughput/latency/renewal measurement, RRAS/NAT
Internet sharing, clean-machine installation, and an independent security
audit. Fixture-driven frontend tests and the no-network EXE smoke test do not
substitute for those checks. See [the full test matrix](../TESTING.md).

Other product boundaries remain: IPv4 only; a shared group credential without
per-peer revocation; no kill switch, DNS-leak policy, seamless roaming, or signed
automatic updater. There is no FIPS or independent cryptographic-audit claim.
See [Security design](../SECURITY-DESIGN.md).

## Integrity and source

The release publishes `SHA256SUMS.txt` for the downloadable artifacts and the
extracted EXE/DLL. Compare the ZIP with PowerShell's
`Get-FileHash .\TrueTunnel-3.1.0-preview.1-windows-x64.zip -Algorithm SHA256`.

The accompanying source archive includes the exact TrueTunnel revision, pinned
wolfSSL source, and native JSON header, along with build instructions and
frontend lockfile/source inputs. The default binary statically links open-source
wolfSSL and is distributed under its GPLv3 terms; TrueTunnel-authored code uses
the MIT option in `LICENSE`. All third-party terms remain in `NOTICE`,
`THIRD_PARTY.md`, and the package's `licenses/` directory.
